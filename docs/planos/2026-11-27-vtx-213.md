# Human-in-the-loop para tools críticas no template web (VTX-213) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tool com `critica: true` não executa no loop do harness: vira ação pendente (`PENDENTE_APROVACAO` + `acao_id`) e só roda, uma única vez, via `POST /api/agentes/acoes/[id]/aprovar` com usuário autenticado e auditoria.

**Architecture:** Repositório `RepositorioAcoes` em `src/agentes/memoria/acoes.ts` (interface + implementação em memória; a de Supabase segue o mesmo contrato e a migração cria `acoes_pendentes` e `acoes_auditoria` com RLS por usuário). `executarAgente` grava a pendência e encerra; `aprovarAcao` (harness) reivindica a ação de forma atômica (`pendente → executando`), executa com AbortSignal e timeout e grava resultado e auditoria. A rota segue o padrão `criarPost(deps)` de `src/agentes/rotas/`. Follow-ups da VTX-177: a tool recebe `{ signal }`; 401/403 do principal desliga o principal pelo resto da execução (circuit breaker) e o fallback assume.

**Tech Stack:** Next.js 15, AI SDK 7 (`MockLanguageModelV4`), Zod 4, Vitest, Supabase (SQL de migração e `auth.getUser`).

**Spec:** `backlog/projeto.yaml` (VTX-213, notas com os follow-ups (a) e (b) da revisão da VTX-177).

## Global Constraints

- Sem rede e sem chave nos testes (modelo falso).
- `ai` só em `src/agentes/harness/`; `src/dominio/` não importa `src/agentes/` (ESLint).
- Zod nas bordas, erros RFC 9457 (`lib/http/problema.ts`), Supabase só com RLS.
- PR com etiqueta `precisa do Samuel` (ferramenta de agente e autenticação).

## Review Focus

- Tool crítica sem repositório de aprovação configurado: falha com `REGRA_VIOLADA` e não executa (teste).
- Duas aprovações concorrentes: só uma reivindica; a outra recebe 409 (teste com `Promise.all`).
- Usuário B aprovando ação do usuário A: 404, sem revelar a existência (teste).
- Tool crítica que estoura o timeout na aprovação: fica `falhou` e não reexecuta (teste).
- `acao_id` que não é UUID: 422 antes de tocar o repositório (teste).
