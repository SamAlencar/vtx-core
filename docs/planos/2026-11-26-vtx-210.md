# Regras do Cursor no template web (VTX-210) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Colocar no template web regras `.mdc` objetivas (stack, API, agentes), um `DESIGN.md` e testes que provam globs, caminhos e exemplos que compilam.

**Architecture:** As regras vivem só em `templates/web-next/.cursor/rules/`. O vtx-core ganha um ponteiro, sem copiar o texto. Caminhos citados nas regras existem como esboços finos (VTX-212 e VTX-177 os completam). Exemplos das cercas de código são extraídos para `tests/regras/` e entram no `npm run typecheck` do template. O CI do vtx-core passa a rodar esse typecheck.

**Tech Stack:** Next.js 15, TypeScript, Tailwind, Zod, Vitest, Supabase JS, unittest Python, GitHub Actions.

**Spec:** `backlog/projeto.yaml` (VTX-210) e auditoria técnica de 25/11/2026 §4 P0 item 2, com a ampliação do `DESIGN.md`.

## Global Constraints

- Sem serviço pago; só o que o template já usa.
- Regras com `alwaysApply: false` e `globs:` não vazios, sem `{` na linha de globs.
- Todo caminho citado nas regras (links e `` `caminhos` ``) existe no projeto gerado por `bootstrap_projeto.sh --tipo web`.
- PR com etiqueta `precisa do Samuel` (regras de agente; job de workflow no vtx-core).

## Review Focus

- Esboços em `src/dominio/` e `src/agentes/` não antecipam o harness real (VTX-177) nem o lint de fronteira (VTX-212): só o mínimo para os caminhos existirem e os exemplos compilarem.
- Exemplos extraídos não divergem das cercas nas `.mdc`.
- `AGENTS.md` do template cita `DESIGN.md`.
- Typecheck do template fica verde no CI do vtx-core, com `permissions: contents: read`.
